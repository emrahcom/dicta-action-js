# Confirmations

The user confirms a risky step before it runs, as `architecture.md` (Display,
Strings, Accessibility), `contract-plan.md` (Confirmation) and
`contract-capability.md` (Confirm over, Capabilities) in `dicta-action-server`
describe. It replaces the rule that such steps run without asking.

- A call to a destructive or external capability asks: the element calls its
  `confirm` with the filled-in arguments and shows the `confirmation` view with
  the text, Continue and Cancel. The status region announces it.
- A `forEach` asks once, before its first item, when one of its calls is
  destructive or external, or is a write call and there are more items than the
  module's `confirmOver` (10 when not set). It first fills in and checks the
  arguments of every item, so a bad item halts the step before the user is
  asked. It shows the first three items, each with the texts of all its calls
  that ask, calling `confirm` only for these, and the number of items with the
  `items` string when there are more than three.
- Continue runs the step. Cancel ends the request: nothing more runs and no
  round is sent.
- A `confirm` that throws, or a missing `confirm`, fails the step as a
  capability error; nothing of the step runs.
- Browser tests for each point, and the focus rule with Continue and Cancel.
