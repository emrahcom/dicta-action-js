# Old outputs

The exchange keeps the outputs of the last two plans; in the reports of the
earlier plans, each included output over 512 bytes is left out. History entries
are stored as `dicta.getHistory` returns them (`contract-protocol.md` in
`dicta-action-server`, Request body; `contract-capability.md` there,
`dicta.getHistory`; `architecture.md`, Storage and Built-in capabilities).

Exchange:

- Each time a plan and its report join a request's exchange, after a plan ran
  and when a saved request goes on in a new page, the element leaves out of the
  reports of every plan before the last two each output over 512 bytes, counted
  as the UTF-8 bytes of its JSON, in `outputs` and in `halt.outputs`. It is not
  listed in `tooLarge`. Smaller outputs, plans, halts, questions, answers and
  added texts stay as they are.

History (`src/history.ts`, `src/builtins.ts`):

- When a request is stored and its JSON is over 16 KB, its outputs are replaced
  by their sizes in `tooLarge` before it is stored, as `dicta.getHistory` does
  today. That code moves from `src/builtins.ts` to the history.
- `dicta.getHistory` returns the stored entry as it is. One still over 16 KB
  goes into the report's `tooLarge` like any output that does not fit.

Tests:

- Unit: an output of 512 bytes stays and one of 513 bytes goes, in `outputs` and
  in `halt.outputs`; the last two plans keep every output; nothing goes into
  `tooLarge`; questions, answers and added texts are unchanged; an entry over 16
  KB is stored with sizes in place of its outputs and one within 16 KB as it is;
  `dicta.getHistory` returns the stored entry.
- Browser: after three plans, the round sends the first plan's large output left
  out and its small one kept, and the last two plans' outputs whole.

Check: `npm run check`, `npm run lint`, `npm run test`, `npm run test:browser`
and `npm run build` pass.
