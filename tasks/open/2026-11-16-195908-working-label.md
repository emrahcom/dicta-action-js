# Working label

The `working` view's label follows the request: "Thinking..." while the element
waits for the server, the running step's text or the plan's label while a plan
runs, and the count of a `forEach` (`contract-plan.md` in `dicta-action-server`,
Label, Steps, Failures and Limits; `architecture.md`, Display and Strings).

Plan check (`src/plan.ts`): a top-level `call` or `forEach` may have `text`, a
string of at most 100 characters; a call in a `do` with `text` fails the check.
The same check as the server's.

Runner (`src/run.ts`): `runPlan` tells the element when a top-level step starts
and, in a `forEach`, how many items are done and how many there are: 0 when the
loop starts, and one more after each item.

Element (`src/element.ts`):

- While waiting for the server, the label is the `thinking` string, shown only.
  A new string `thinking`: "Thinking...".
- While a plan runs, the label is the running step's `text`, or the plan's label
  without one, or empty without both. During a `forEach`, it ends with the
  count, such as `40/80`, after a space when there is a text.
- Announcements stay as they are: only the plan's label.

Tests:

- Unit: the plan check takes a step text up to 100 characters and refuses a
  wrong type, 101 characters and a text in a `do`; the runner reports step
  starts and the loop count from 0 to the number of items.
- Browser: "Thinking..." while the server has not answered, also as overridden
  by `strings`; a step's text replaces the label while it runs and the label
  comes back after it; a `forEach` shows its count as it goes, with and without
  a text; step texts and counts are not announced.

Check: `npm run check`, `npm run lint`, `npm run test`, `npm run test:browser`
and `npm run build` pass.
