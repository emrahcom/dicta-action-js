# Plan check

Check a plan before any step runs, as `architecture.md` (Plan runner) and
`contract-plan.md` in `dicta-action-server` (Steps, Include output, References,
Failures, Limits) describe.

- A function that takes a plan and the site context and throws with the reason
  when the plan fails the check: the limits (50 steps, 16 KB, a label of 200
  characters), the step forms, every `call` naming a capability, `args` matching
  its schema or `{}`, every reference pointing to an earlier step or a `forEach`
  item, every `forEach` referring to an earlier step, and `includeOutput` a
  boolean on top-level steps only.
- The same check as the server's (`dicta-action-server/src/plan.ts`): properties
  read with `Object.hasOwn`, never with `in`; a reference stands for any value;
  a string that starts with `$$` is not a reference.
- A schema check that the plan runner can use again once references are filled
  in.
- Unit tests for each failure and for a valid plan, with `__proto__` and
  `toString` as argument names.
