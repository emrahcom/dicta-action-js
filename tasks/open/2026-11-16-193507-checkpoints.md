# Checkpoints

The server marks every few plans as a checkpoint, and the user decides whether
the request goes on (`contract-plan.md` in `dicta-action-server`, Checkpoint,
Confirmation and Failures; `architecture.md`, Display and Strings).

Plan check (`src/plan.ts`): a plan may have `checkpoint`, a boolean, and
`progress`, a string of at most 200 characters, the same check as the server's.
Any other value fails the check.

Runner (`src/run.ts`): before the first step of a plan with `checkpoint: true`,
after the stop check of that step, `runPlan` asks with the plan's `progress`.
Continue runs the plan, with the steps' own confirmations as before; Cancel
stops at step 1, which does not run, with the halt code `cancelled`.

Element (`src/element.ts`):

- The confirmation view shows the `progress` as plain text in the `text` part,
  or the `checkpoint` string when the plan has none, and it is announced like
  any confirmation.
- A new string `checkpoint`: "Do you want to go on?".

Tests:

- Unit: the plan check takes `checkpoint` and `progress` and refuses a wrong
  type and a progress of 201 characters; a checkpoint asks before step 1 and
  only once; Cancel halts at step 1 with `cancelled`; a plan without
  `checkpoint` does not ask.
- Browser: a checkpoint shows its progress; without one it shows the
  `checkpoint` string, also as overridden by `strings`; typed text does not
  answer it; Continue runs the plan.

Check: `npm run check`, `npm run lint`, `npm run test`, `npm run test:browser`
and `npm run build` pass.
