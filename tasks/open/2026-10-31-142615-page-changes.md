# Page changes

A request goes on in the new page when a step loads a page, and ends when the
page changes at any other time, as `architecture.md` (Storage) and
`contract-protocol.md` in `dicta-action-server` (Page changes, Report) describe.

- On `pagehide` while a step runs, the element saves the request in
  `dicta-action-saved`: `savedAt`, `requestId`, `text`, `exchange`, the running
  plan, the report so far and the running `step`, with `item` and `do` in a
  `forEach`.
- When the element has its `server` and `module`, it takes a saved request out.
  One saved at most 60 seconds ago goes on: the plan is reported with the halt
  code `navigated` at the step that was running, with the outputs so far, and
  the next round is sent with the new page's `state`. An older one is added to
  the history as cancelled, with its report and the same halt.
- On `pagehide` at any other time, while the element waits for the server or a
  question or a confirmation is open, the request is added to the history as
  cancelled, with everything done so far, also a report not sent yet.
- Unit tests for the report so far, and browser tests with real page loads for
  each point.
