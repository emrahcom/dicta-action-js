# Element

The `<dicta-action>` element with a request that ends in one round, as
`architecture.md` (Delivery, Element, Requests, Display, Strings, Accessibility)
describes. Plans and questions come in their own tasks.

- Importing the package defines `<dicta-action>`, with a shadow root. The
  `server` and `notice-duration` attributes, the `module`, `getToken` and
  `strings` properties and the `submit(text)` method.
- `submit(text)` with no request running starts a request and sends its rounds
  with the round client. While a request runs, `submit` is ignored for now.
- Replies: done (a notice with its text, or nothing), stop and info end the
  request with their views. A round client error ends it with the `error` view
  and logs the cause to the console. Until their tasks, a plan or a question
  ends the request as an error.
- Views and notices as Display describes: `working` with the indicator and
  Cancel, `stop`, `error` and `info` with Close, notices with `notice-duration`
  and the pointer and focus rule. Cancel ends the request; a response after it
  is ignored. Texts are set as plain text.
- The CSS parts and the custom states of Element, the strings `cancel`, `close`
  and `error` with `strings` overrides, and Accessibility: the status region and
  the focus rules.
- Browser tests with Playwright, in Chromium, Firefox and WebKit, set up as in
  `dicta-js`, with the server's responses faked in the page. One test for each
  point above.
