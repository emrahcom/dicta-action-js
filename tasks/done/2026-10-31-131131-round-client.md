# Round client

Send one round to the server and return its reply, as `architecture.md`
(Element, `server` and `getToken`; Requests) and `contract-protocol.md` in
`dicta-action-server` (Round, Request body, Response body, Errors) describe.

- It takes the server origin, the module, `getToken` when set, and the round's
  `requestId` (left out in the first round), `text` and `exchange`.
- The body: those fields, `state` from `module.state.run()`, the site context
  from the module, and `time`: the browser's local time to the second, with the
  offset as numbers, `+00:00` too, never `Z`.
- `POST <origin>/dicta-action/v1/round`, ignoring a path in the origin.
  `Authorization: Bearer <token>` when `getToken` is set. The token is kept
  between rounds; a `401` gets a new one and one more try with the same body.
- It returns the `requestId` and the reply. These end in an error that names the
  cause: another HTTP error, with the server's `error`; a second `401`; a
  network failure; no response after 60 seconds; a reply type it does not know;
  `getToken` or `module.state.run()` throwing. No retry.
- No checks of the reply beyond its type: the server checks it.
- Unit tests with a fake `fetch` for each of these, and for the time format with
  a positive, a negative and a zero offset.
