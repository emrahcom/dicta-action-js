# Test cleanups

Test fixes from the code quality review of 2026-11-20. The tests check the same
behaviour as before, with less repetition, in the file a reader would look in.

- `test/browser/plans.spec.ts`: the tests use the shared `holdStep`,
  `finishStep` and `planThenHold` in place of their own copies, and
  `holdDeletes` goes.
- `test/browser/page.ts`: `inState` and the part selectors used by several spec
  files, such as the notice, the label and the status region, are shared from
  here. Its header comment is wrapped evenly.
- `test/browser/fixes.spec.ts`: its one test moves to
  `test/browser/announcements.spec.ts`, and the file goes.
- `test/storage.ts`, new: one fake session storage, with a limit, and a broken
  one, shared by the unit tests that need them.
- `test/history.test.ts`, new: the history and saved request tests move out of
  `test/builtins.test.ts`, which keeps the tests of the built-in capabilities.
- `test/run.test.ts`:
  - the `run` helper takes the answer to confirmations and the callbacks it
    needs, so no test calls `runPlan` with all its arguments, and no test sets a
    shared answer and must set it back;
  - the second test of a missing `confirm` goes; the first covers it;
  - it uses `bytes` from `src/run.ts` in place of its own copy.
- `test/round.test.ts`: `assert.rejects` checks the message in the short form
  everywhere, and the three local time tests become one table.

Check: `npm run check`, `npm run lint`, `npm run test` and
`npm run test:browser` pass, with no checked behaviour lost.
